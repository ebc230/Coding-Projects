# Lightsaber App Carothers

For this app when I first started before I did anything related to looks and actual lightsaber looks part I imported the Accelerometer and outputted the values of x, y and z to start to understand how to decipher the information. First I started by just rotating my phone and seeing how the values would change based on orientation, I figured out the values x, y, and z hovered around when the phone was straight up and straight down, x was about 0.02 and Y about -1 and z about 0. After I figured out these numbers as gauges I made an on/off button that would only turn on if facing straight up and only off if facing straight down. I made an if statement that compared each x, y, and z value to 2 numbers as a range to be in that would dictate which direction it was facing, I also gave each number about 0.4 grace to allow for some tilt that would be realistic in use and easier to use since the user wouldn’t have to keep adjusting to get a perfect straight angle. I did a few trials for this window to make sure it wasn’t to big where direction wouldn’t matter but not be to specific. Then I started to work on the sound for these 2 actions (one/off). I imported the sound files and put the require statements for each sound into a list. I imported audio player to be able to play the sounds. I have one audio player language and just replace the sound in the player with the object in the sounds list that corresponds to the action and then play the player. The I started to working on the swing and crash, still didn’t start any real interface work yet just numbers displayed and a button. I moved my phone in a swing motion and took screenshots and screen record to see how the numbers reacted, then I started to make windows, and since all numbers would change, but all the windows I would be making were not reliable, if the phone stayed tilted in one direction but not moving it was getting counted as a swing. I was thinking that there has to be some overall value or magnitude I can use for all theses values and not have to judge for each single one for a swing I’m really judging overall change regardless of direction. So I asked ChatGPT if there is some kind of magnitude I can get from x, y, and z values of accerlometer and it gave me a formula for magnitude I didn’t know, sqrt(x^2 + y^2 + z^2)(Euclidean norm), this would give me magnitude overall. I then used this for swing and fixed the orientation issues since the direction isn’t a factor anymore for the number, I still had to figure out when the cap would be that would consider a swing a swing, I tried many values and 1.4 seemed the best, you don’t have to swing crazy hard for it to register but also it doesn’t get set off with any movement either. I then worked on crash, I created a new variable sw that was true if a swing was last detected to a crash wouldn’t go off if there was no swing.  I also made a new variable that was update in useEffect whenever x,y, and z changed that would have the value of the last magnitude value. This originally checked if the lastMag - most recent mag was big enough, it changed between 0.5 and 1 difference. However with this testing it was unreliable because if the swing it self did not have a large magnitude the crash of a fast deceleration wouldn’t be big or enough to be detected but is still a crash. So then I played around with percentage values and settled on it 40% of the last magnitude was greater than the most recent mag it was significant enough to be considered a crash, the crash has to be pretty hard/significant to prevent a crash going off just at the end of a swing, this helped to make it more scalable to different swings. I also ended up playing with the update speed of the accelerometer, I changed it to 200 to make it more sensitive to be able to more accurately detect crashes since they are mostly fast. I also with the sounds, if a crash is detected it will override the swing soon, which makes sense since with a crash a swing isn’t completed since it stops. This crash will also be detected if you flick the phone like end a swing with a flick. Also sometimes if you end a swing with a sharp end it will count as a crash. I also ended up getting rid of the z part for the on/off if statements to make it easier to be turned on since up orientation isn’t really dependent on depth and that number can mess with it in the if statement if the phone was moving. Then I finally added the lightsaber image, the top part disappears and appears based on opacity levels of the image. Also since for Apple and Android the y value is flipped, apple is pos for up and android is negative for up, I used platform to get the OS to be able to determine the right values to be compared for the up and down orientation. For this app overall for every single value used it was a ton of trial and error to get the values that made to most sense to both usability and function of the app.
